# 游戏体验设计 SKILL

用于界面、流程和交互重构。

1. 先写清：玩家从哪里进入、完成什么、看到什么反馈、数据如何变化，再决定布局；禁止继承旧布局只做局部美化。
2. 信息层级按实际操作频率组织：核心状态和常用行动优先；技能、长说明等进入分页或浮窗，不挤占中央区域。
3. 工具面板与内容面板是独立层级。地图工具栏默认左侧、可拖动并保存位置；顶部栏不覆盖它。
4. 所有拖放、保存、装备、购买、恢复操作有清楚的可用/禁用状态和即时反馈；空状态告诉玩家下一步。
5. 视觉由规则模块按规则书设计，宿主不写死深浅色或固定布局。要求：可读、可滚动、可缩放、响应式、错误状态清楚。
6. 地图层级固定：地图底层；聊天栏与右侧面板同层；可拖动地图工具栏在其上。多地图分页，每张地图独立保存背景、比例尺、Token、范围与测量；分页/平移/缩放是玩家本地视图，不联动他人镜头。
7. 左键选择/拖动对象，右键拖动地图。R/M 只切换工具，左键开始并再左键固定；范围配置用真实距离与单位按比例尺换算，点击处显示上下文编辑器。
8. 通用地图 Token 与角色 Token 分离；物体、小队、地点、危险和注释不得进入角色列表、角色资产或先攻。
9. 完成标准是真实流程可走通，不是按钮存在。至少验证：入口、操作、计算、保存恢复、AI读取、单人与联机一致性。
10. **固定尺寸框规范（强制）**：内容展示区块（角色设定、描述、列表、长文本等）一律使用固定尺寸比例的框（固定高度），内容超出用内部滚动（overflow-y:auto）；禁止动态高度/内容撑开式布局；宿主插件外层容器规则不变（见 plugin-authoring）。
