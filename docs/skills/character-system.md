# 角色系统 SKILL

用于角色创建、现行角色卡、背包、装备、法术、标签、权限、版本与导出导入。

## 统一角色体验
- 创建、查看、编辑使用同一份角色数据和同一规则组件；查看默认只读，拥有者与 GM 可原位进入编辑；禁止维护两套样式和两套字段。
- 编辑现行角色不出现创建语义（投点模式/初始装备）：属性就是可修改最终数字；装备是正规背包。
- HP、AC、先攻、速度和核心属性常驻总览；总览已完整呈现的种族与属性不再建重复分页。自定义背景显示真实名称和正式数据，禁止占位名。
- 弹窗必须支持取消、关闭按钮、点击遮罩和 Escape；浮窗、骰子日志与弹窗层级明确，打开弹窗时清理其他浮动层，任何路径不得留下卡死遮罩。
- 每次保存先生成 GM 历史备份，支持字段差异对比和恢复；刷新、重启、单人与 P2P 后一致。

## 角色列表与地图
- 地图点头像只选中右侧角色条目，不打开角色卡；条目点击只选中；通过条目显式"角色卡"按钮打开。
- 玩家/友方/敌人/NPC/自定义分类分页；可编辑角色拖到分页即改分类，不在条目中塞分类按钮。

## 物品与背包
- 物品统一为数据条目：id/名称/类别/数量/单价/总价/重量/装备状态/装备槽/规则来源/完整说明/效果。
- 可装备性由物品数据驱动；只有带装备槽或明确可装备标记的物品显示装备操作；套组、消耗品和普通杂物默认不可装备。
- 套组展开为明确内容并保留来源；药水等可直接调数量；卷轴先选法术、环位与版本再动态算价。
- 护甲只能从背包已有护甲装备；武器攻击和伤害自动汇总属性、熟练、魔法与效果；负重只在背包管理。
- 创建页物品区至少预留 5 个稳定栏位，避免动态增删造成布局跳动和误操作。

## 标签
- 法术、特性、装备、状态、熟练等只使用全局 TrpgTag；同一数据在创建页和角色卡只有一种标签与一种浮窗。
- 浮窗显示完整规则信息、来源与结构化字段，不使用摘要占位；来源必须是当前规则系统内可打开的精确路径。
- 自动加值保存来源与计算痕迹；背景属性提高记录分配前、提高值、应用后和当前值。

## 职业成长
- 职业、子职业、战斗风格、超魔、魔能祈唤及嵌套选择由规则数据驱动，按 1—20 级分页显示解锁条目、完整说明、前置、数量和来源。
- 切换职业/子职业/选择项时，旧自动特性、熟练、法术和派生效果立即移除，新内容立即应用并保存。
- 三分之一施法者、子职业法术表、固定法术与动态选法必须读取子职业数据，不得把战士或游荡者一律判定为非施法职业。
- 保存后的职业与子职业能力生成可快速查阅的标签，保留精确规则链接与结构化详情。
- 种族、职业、子职业和嵌套能力复用同一套自适应规则卡/规则条目/选择区/来源浮窗；4级、8级等成长显示为明确规则选择条目，先选"属性提升/专长"分支再填写具体值；更换选择撤销旧效果、应用新效果、保留来源记录。

## 图片素材
- 一张原图依次生成 3:4 垂直立绘和圆形头像；PNG 保留透明；吸管从原图采样背景色并提供容差与柔边。
- 裁剪工具独立窗口，角色卡只展示结果；宿主接管新窗口时不得误报浏览器拦截。
- 角色卡 data.assets 只允许 avatarFramed 与 portrait 两键，与顶层 avatarUrl 只存 `/Ruler/<系统>/存档/<冒险>/characters/<id>/icon/<文件名>` URL（或空），禁止 base64 dataURL；AI 修改角色卡时保留既有 URL 原样。

## 导出与导入（宿主能力）
- 宿主提供角色卡导出/导入：`POST /api/characters/export`（角色 JSON+立绘 base64 单文件包，跨存档/跨团携带）、`POST /api/characters/import`（恢复为新角色、新 id、立绘重新落盘 icon/）。角色卡顶栏「导出卡/导入卡」按钮。
- 插件/角色功能不得绕过该机制另造导出格式；导入生成的 id 不得写死进规则数据。
