# 规则专属角色卡插件 API 参考（character-sheet）

## 宿主动态链接

规则系统切换时，宿主检查该规则插件的 `manifest.type === "character-sheet"`：

- 角色创建/编辑在**独立窗口**（`/character-create.html?system=&id=`，宿主接管 window.open 为原生窗口）：页面内加载插件代码，调用 `handler.renderCreate(container, ctx, done)`。
- 角色卡详情在**独立窗口**（`/sheet.html?id=<tokenId>`）：宿主按标准字段通用渲染。
- 未注册角色卡插件的规则使用默认通用表单。

## 通用原则

本项目是**通用 TRPG 平台**：AI 自动解析任意规则书并制作工具。本文件只定义"必须从规则书提取并完整实现"的通用标准；**具体规则参数（DND 的购点/生命骰/职业/AC 公式等）一律来自该规则书解析产物**（compressed/rule_settings.json、rule_tree.json、压缩表、源文），禁止写死为任何规则的数值。

## 角色卡游戏体验完整标准（通用，缺一即未完成）

1. **完成标准 = 完整玩家游戏体验，而非执行完毕任务**：验收 = 真实玩家能否按该规则书走完真实流程（属性生成→角色构成→装备→掷骰→升级）；任何环节只做表面控件即未完成。
2. **规则书驱动**：字段、选项列表、公式、流程都从该规则书解析产物提取（规则定义了什么就做什么），不得套用其他规则结构。
3. **属性生成默认全做**：提供该规则书定义的全部标准生成模式（示例 DND：购点/骰点 4d6 取最高3个×6/标准数组/手动），缺任一=未完成；骰点**自动输出结果不展示过程**、可重复掷；手动模式必须保留。
4. **内容范围 = 官方内容**：选项列表覆盖该规则书核心+官方扩展（示例 DND：含奇械师·艾伯伦：奇械锻炉）；默认不收录第三方，但留手动/自定义输入入口便于动态扩展。
5. **掷骰由玩家驱动**：规则中由玩家掷骰决定的值（示例 DND：HP/属性）提供掷骰按钮自动出结果可重复掷、可手动输入；禁止默认填最大/均值。
6. **编辑模式不做完整创建流程**：编辑已有角色简单回填即可。
7. **角色升级流程（Level-up）**：按该规则书升级规则提供完整流程（玩家驱动：成长骰、受等级影响的派生值自动更新、能力/专长选择提示、法术类更新提示），数据落盘；规则书定义了升级就必做，缺失=未完成。
8. **自动计算链完整**：按规则书公式完整推导派生值并实时联动（示例 DND：AC 护甲公式/先攻=敏修/DC=8+熟练+施法属性修正），禁止只给"建议值"。
9. **玩家视角验收**：交付前模拟真实玩家按该规则书完整创建+升级一次并核对全部派生值。
10. **全方面技术核查**：滚动/自适应属类别问题，交付前检查所有独立窗口页面（创建/详情/查看/树导航）内容超长可滚动、缩放正常。

## 插件结构

```
Ruler/<系统>/plugins/character-builder/
  manifest.json   { "id": "character-builder", "name": "…", "version": "1.0.0", "type": "character-sheet", "description": "…" }
  index.js
```

## index.js 骨架（照此填充业务）

```js
module.exports = {
  register(api) {
    api.registerCharacterSheet({
      renderCreate(container, ctx, done) {
        // container: 宿主提供的表单容器（div，已清空，可写 innerHTML）
        // ctx: { system, token(编辑模式非空，用于回填), fetch(path), openRuleFile(file) }
        container.innerHTML = '…表单HTML…';
        // 宿主点击"保存"时调用 collector()：
        //   返回 { name, displayName, color, data } 保存角色
        //   校验失败返回 null（并已在表单显示错误提示）
        done(function () {
          var d = { /* 收集表单值 */ };
          if (!ok) { showError(); return null; }
          return { name: d.name, displayName: d.displayName, color: d.color, data: d };
        });
      }
    });
  }
};
```

## 关键约定

- `data` 结构按规则自定义，但顶层建议包含 `HP: {current, max}` 与 `AC`（宿主用它们同步地图角色血量/护甲）；并按标准字段命名，独立窗口通用渲染可显示：`name/race/class/background/level/hitDice/proficiency/attackBonus/abilityScores/abilityMods/skills/spells/equipment`。
- `renderCreate` 的 `done` 由宿主在保存时调用一次，`done(collector)` 传收集函数。
- 校验失败：collector() 返回 `null` 并在表单内提示。
- 词条悬停（`data-term` + `api.bindTermTips`）与打开式速查（`ctx.openRuleFile`）是**通用机制，所有插件必须使用**。
- 插件内部样式用内联 style 或本插件自带 `<style>` 块（避免污染全局）。
- **元素定位必须与实际属性匹配**：容器内统一 `container.querySelector(...)`；class 元素用 `.class`、id 元素用 `#id`。禁止用 `#id` 前缀查询只有 class 的元素（如 `querySelector('#cb-ability-in[data-key="str"]')` 会返回 null 并在运行时抛错）。

## 抽象规范：角色卡与开卡流程分离（通用）

> 用户2026-08-05需求固化。创建角色必须先选模式：**开卡流程** 或 **已有角色卡（编辑）**。开卡是一次性引导（随机骰点/购点/标准数组/手动、起始装备分配、熟练/豁免/专长初选），完成后进入常驻角色卡；开卡控件**不常驻**在角色卡页面上。

1. **模式二选一**：进入创建时先呈现"开卡流程 / 编辑已有角色"入口。开卡流程=分步引导（属性生成→构成→装备→技能/豁免/专长→法术→完成）；编辑=简单回填已有 data。
2. **开卡流程是独立阶段**：骰点/购点/起始装备选择只在开卡中出现；角色卡页面展示开卡结果（最终属性、装备清单、技能/豁免/专长列表），不再重复摆放生成控件。
3. **自动更新链**：熟练/豁免/起始装备/专长/技能数量/额外加值随创建与升级自动匹配更新（按规则书公式计算派生值，不手动维护）。
4. **角色卡多页布局**：按功能分页（示例：背景/信息、属性、道具、法术）。玩家可在页间切换速查。
5. **选择精简化**：法术选择先给"可选环位+可用数量"，玩家选环位后以列表选择法术，法术效果动态小窗展示；V/S/M 等标签显示实际意义、标签化排列、悬浮小窗显示定义与效果。
6. **规划层级**：整体结构先规划（模式选择→开卡→多页角色卡→各页组件），保证有效且美观。
